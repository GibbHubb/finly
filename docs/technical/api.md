# API

## Conventions

- **Base URL:** `/api/v1` for the application API; `/health` sits at the root. Locally
  `http://localhost:8000`; the interactive schema is served at `/docs` and the raw one at
  `/openapi.json`.
- **Versioning:** the `v1` path prefix. There is no second version.
- **Content type:** JSON in and out, except `POST /auth/login` (an OAuth2 form,
  `application/x-www-form-urlencoded`), the CSV import routes (`multipart/form-data`) and the
  year-in-review PDF (`application/pdf`).
- **Money:** amounts are decimal strings (`"120.00"`), never floats.
- **Currency conversion when rates are unavailable:** finly never invents a rate. If the FX
  provider cannot be reached, a write that needs a conversion (a foreign-currency transaction, a
  split, a base-currency change) is refused with **503** and nothing is stored; a CSV import or
  bank sync that needs one stores nothing and says so. A transaction already in the base
  currency needs no rate and always saves. (F52 removed the old silent 1:1 fallback; F55/F57
  made the refusal explicit; `rates_service.convert_amount` returns `None`, never a guess.)

## Authentication

- `POST /api/v1/auth/login` takes `username` (the email) and `password` as a form and returns
  an access token and a refresh token. Send the access token as `Authorization: Bearer <token>`.
- Access tokens live `ACCESS_TOKEN_EXPIRE_MINUTES` (default 15). Refresh tokens live
  `REFRESH_TOKEN_EXPIRE_DAYS` (default 14), are one-time use and rotate on every
  `POST /auth/refresh`; replaying a used one revokes the whole session (F42).
- `POST /auth/logout` revokes the session server-side.
- Five failed logins for one email inside the window answer **429** until it passes (F42, F60).
- The `/api/v1/tasks/*` routes are for Vercel Cron and require the cron secret, not a user token.

## Errors

- FastAPI's envelope: `{"detail": "<message>"}`. Request validation failures are **422** with
  `detail` as a list of field errors.
- Status codes in use: 400 (bad input the schema cannot express), 401 (no or bad token),
  404 (not found, or not yours), 409 (duplicate, e.g. a second budget for the same
  category and month), 422 (validation), 429 (login lockout), 503 (a dependency is not
  configured, e.g. GoCardless keys).
- An unhandled error is **500** with `{"detail": "Internal error", "error_id": "<id>"}` and an
  `X-Request-ID` header. The exception text is never returned; quote the `error_id`.

## Pagination, filtering, sorting

`GET /transactions/` takes `skip` (default 0) and `limit` (default 100, max 500), and filters
`date_from`, `date_to`, `category`, `type` and `tag`. Lists are returned newest first. Other
lists are small per user and are not paginated.
